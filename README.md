# mini-analizador-datos

Mini proyecto de análisis de datos en Python que calcula estadísticas básicas y aplica prácticas ágiles de calidad, revisión de código y estándares de formato.

## Reflexión

En esta actividad desarrollé en GitHub un pequeño programa de análisis de datos que recibe una lista de números y permite calcular el promedio, el valor máximo, el valor mínimo y la cantidad de datos.

Lo más importante que aprendí fue comprender la importancia de trabajar siguiendo un proceso ordenado y controlado. Utilicé una rama independiente para realizar los cambios sin modificar directamente la versión principal del proyecto. Esto me permitió entender que una rama funciona como un espacio de trabajo donde puedo realizar cambios y pruebas antes de integrarlos al proyecto principal.

También apliqué Coding Standards utilizando Black como estándar de formato y agregando documentación a las funciones. Esto permite que el código tenga una estructura más clara y facilita que otras personas puedan entenderlo y mantenerlo.

Posteriormente realicé un Pull Request y un Code Review. Entendí que el Pull Request permite solicitar que los cambios sean revisados antes de incorporarlos a la rama principal. La revisión de código permite detectar errores, mejorar la estructura y mantener criterios comunes dentro del equipo.

Una de las principales enseñanzas para mí fue comprender que trabajar de manera ágil no significa simplemente trabajar rápido, sino trabajar de forma ordenada, haciendo cambios pequeños, revisándolos y corrigiéndolos oportunamente. Esto ayuda a reducir el retrabajo y evita llegar al final del proyecto con muchos problemas acumulados. Lo relaciono con lo visto en clase sobre evitar el “Big Bang” y reducir los problemas que aparecen cuando la integración se realiza demasiado tarde.

Esta experiencia también la relaciono directamente con mi trabajo. En algunas ocasiones he comenzado a elaborar informes de Power BI con la intención de avanzar rápidamente, pero posteriormente aparecen cambios porque no se había definido completamente lo que necesitaba el usuario. Si hubiera tenido desde el principio una conversación más clara con el director comercial sobre los requerimientos, probablemente habría evitado parte del trabajo duplicado.

Por eso considero que estos principios no deberían aplicarse solamente a un proyecto de programación. También pueden utilizarse en el trabajo diario, porque permiten organizar mejor las tareas, recibir retroalimentación a tiempo y realizar correcciones antes de que el costo del cambio sea mayor.

Finalmente, comprendí que la agilidad no consiste en hacer las cosas sin planificación, sino en planificar, organizar, trabajar de forma ordenada, entregar avances, revisar y mejorar continuamente. A partir de esta experiencia, considero que puedo aplicar estos principios en mis actividades laborales para reducir reprocesos y trabajar de una manera más organizada.
